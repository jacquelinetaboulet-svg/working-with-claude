# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A workshop repository. The code is `ops-dashboard`: a read-only Spring Boot 3.2 / Java 17 REST API (Spring JDBC + Flyway, no JPA) over PostgreSQL, plus a framework-free JavaScript page in `src/main/resources/static/` served by Spring Boot on the same origin. `workshop/` and `docs/` hold the labs, tickets (`docs/tickets/TODO-23x.md`) and reference files. `wall/` and `gift/` are unrelated static workshop pages.

## Commands

```bash
./mvnw test                                                   # Java suite (25 tests, H2, no DB needed)
./mvnw test -Dtest=DashboardControllerTest#healthReportsUpAndTheFixedToday   # one Java test
npm install && npm test                                       # frontend suite (45 tests, Jest + jsdom)
npx jest src/test/javascript/api.test.js -t "status line"     # one JS file / test name
SPRING_PROFILES_ACTIVE=demo ./mvnw spring-boot:run            # run on in-memory H2 → http://localhost:8080
docker compose up -d db && ./mvnw spring-boot:run             # run on PostgreSQL 16 (default profile)
```

There is no linter and no frontend build step. No CI is active; `docs/examples/ci.workflow.yml` is a template.

## Architecture

- **"Today" is pinned to 2026-09-21** (`ops.today` → `Clock.fixed` bean in `ClockConfig`). Always use the injected `Clock`, never `LocalDate.now()` without it. Default ranges are "last 30 days ending today" (`DateRange.resolve`). The frontend gets "today" from `GET /api/health`, never from the browser.
- **Request flow:** controller → `DateRange.resolve(from, to, clock)` → `DashboardRepository`/`VendorRepository` (plain SQL via `NamedParameterJdbcTemplate`) → Java records serialized as JSON. Counting rules (by `delivered_date`, on time = `delivered_date <= promised_date`, revenue excludes cancelled orders, tickets by `opened_at`) are in the `DashboardRepository` Javadoc.
- **No input validation yet** on `from`/`to`/`limit` (malformed date → 500); that is TODO-232, and `DashboardControllerTest` currently asserts the 500.
- **Profiles:** `postgres` (default, env overrides `DATABASE_URL`/`DATABASE_USER`/`DATABASE_PASSWORD`) and `demo` (H2 in PostgreSQL mode, same migrations). All Java tests use `@SpringBootTest` + `@ActiveProfiles("demo")` against the real seed.
- **Seed data** (`db/migration/V2__seed.sql`), `docs/data/deliveries-last-30-days.csv` and `docs/data/ANSWER-KEY.md` are generated by `tools/make_seed.py`. Expected figures in both test suites come from the answer key; changing the seed means changing the tests.
- **Frontend (`app.js`):** one IIFE exporting `initApp(document, fetchImpl)` plus pure helpers; exports via `module.exports` under Jest, `window.OpsDashboard` in the browser. Charts are inline SVG built with `createElementNS`.

## Frontend test harness

`src/test/javascript/setup/loadApp.js` loads the real `index.html` body into jsdom, injects a fake `fetch` serving `FIXTURES` for every `/api` route (`overrides.failing` makes paths return 500), then runs `initApp` and awaits `app.ready`. `harness.test.js` fails if any `id` in `index.html` is not listed in `REGISTERED_IDS` (and vice versa): **every new element id must be registered there.** A new API endpoint also needs a route in `createFakeApi`.

## Rules

- `pom.xml` dependencies are frozen. Any change needs a CHG ticket.
- Definition of done (`docs/PRE-WORK.md`): run `./mvnw test` and `npm test` and report both counts; register new element ids in `loadApp.js`; restart the app so the change can be checked at http://localhost:8080.
